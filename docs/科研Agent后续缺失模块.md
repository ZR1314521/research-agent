# 科研 Agent 后续缺失模块

更新时间：2026-07-13

这不是固定开发工作流，也不是让 Agent 按顺序执行的任务表。它只是能力缺口清单，后续可以按实际用户问题独立调用和实现。

## 不变边界

- 模型理解用户、决定是否调用工具、选择和组合工具、生成最终回答。
- 代码只负责模型通信、真实工具、权限、安全、持久化、取消和错误交付。
- 不增加关键词意图路由、自定义决策 JSON、固定科研步骤、固定工具顺序或场景回答模板。
- 用户结果验收保持旁路：可以观察和报告，但不能修改提示词、工具选择、执行结果或最终回答。
- 所有数量、超时、上下文和安全保护应可配置；非安全需要不锁死。

## 已完成的基础（不要重复造）

- DeepSeek 原生 assistant/tool-call/tool-result 对话链路。
- 模型直接回答与自由组合工具，不再依赖 Decision JSON。
- 成功工具结果在模型后续失败时仍会如实交给用户。
- 工作区读取支持分页、尾部读取和带行号命中内容的搜索。
- 工作区越界保护与常见根目录写法容错。
- 旁路用户结果验收报告及网页查询接口。
- 本地网页聊天、会话、上传、状态和前端构建仍可用。

## P0：下一阶段最需要

### 1. 长对话上下文管理

保留原生消息、工具调用和工具结果；接近模型上下文上限时再做可追溯压缩。压缩策略由模型能力和提供商窗口决定，不固定截取最后 N 条，也不按字符粗暴裁剪。

用户效果：长任务里不用反复说明，上传文件、已经做过的检查和当前目标不会轻易丢失。

### 2. 单一会话与运行存储

把当前旧 JSON 会话与 RunStore 镜像收敛为一个权威存储，保留迁移读取能力。

用户效果：刷新网页、恢复会话和查看成果时状态一致，不出现“界面说完成、磁盘记录却不同”的情况。

### 3. 通用权限管理器

权限按真实操作能力判断：只读、联网、创建、覆盖、移动、删除、执行代码。仅不可逆或高风险动作请求确认，不按任务类型预设流程。

用户效果：普通读取不被频繁打断，危险操作又不会静默发生。

### 4. 统一工具运行协议

所有工具统一返回真实消息、结构化数据、成果路径、可恢复错误和取消状态；支持幂等标识、超时配置和中途取消，但不规定工具组合顺序。

用户效果：工具报错后模型能理解原因并换方法；已经成功的成果不会因为最后一次模型请求失败而消失。

### 5. 真实模型用户验收台

把典型用户请求作为可编辑样例运行，记录最终回答、真实工具调用、错误、耗时、成果是否存在和是否发生副作用。语义质量可以由人工或独立模型评价，但评价结果绝不能进入当前运行的决策链。

用户效果：后续能直接看“用户问了什么、最终拿到什么”，而不是只看单元测试和内部 JSON。

### 6. 旧规则运行时退役

当前关键词 IntentParser、Rule Planner、Decision schema 和固定 ResearchWorkflow 已从主聊天入口隔离。待旧调用方迁移并补齐兼容测试后，删除这些孤立模块和对应旧测试。

用户效果：仓库本身也不再给维护者造成“应该继续往关键词和工作流里加规则”的误导。

## P1：科研体验关键能力

### 7. 文档理解层

PDF、DOCX、表格、图片 OCR、章节结构、页码定位、表格与公式提取，并把证据位置返回给模型。

### 8. 浏览器与网页研究工具

支持搜索、打开页面、下载公开资料、读取动态网页和保存来源；工具只提供网页能力，不内置“先搜几轮再筛选”的固定流程。

### 9. 引用与事实核验

DOI、题名、作者、期刊、年份、撤稿状态和正文证据位置核验；输出可追踪证据，不用硬编码期刊结论或论文名单。

### 10. 安全代码与数据运行环境

为 Python/R/命令行提供隔离目录、资源限额、超时、取消、产物回收和明确的联网权限。

### 11. 成果预览、版本和差异

网页端直接预览 Markdown、PDF、DOCX、CSV、图表；保存版本、显示差异、允许恢复，不覆盖用户原文件。

### 12. 提供商与模型管理

网页配置兼容 OpenAI 协议的模型地址、模型名、密钥引用、思考模式和上下文能力；保持提供商中立，不为某个模型写语义分支。

## P2：产品化能力

### 13. 插件 / MCP 能力加载

运行时发现并注册新工具，校验参数和权限即可供模型使用；不需要再修改中心路由器。

### 14. 长任务后台运行

断开网页后继续执行，支持恢复、暂停、取消、进度事件和失败后从真实检查点继续。

### 15. 用户反馈入口

网页提供“结果有用 / 没用、原因、期望结果”记录，关联当前请求和成果；反馈只进入离线分析，不即时操纵 Agent。

### 16. 安装、升级和诊断

一键启动、依赖自检、端口检测、日志打包、可回滚升级，避免要求普通用户理解 Python、Node 或环境变量细节。

## 每个新模块的最低验收

- 用户可以用自然语言触发，不要求记固定命令。
- 模型可以选择不使用、使用一次或自由组合。
- 不靠关键词表判断用户想做什么。
- 不要求模型输出自定义决策 JSON。
- 不把某个科研场景写成唯一允许的步骤链。
- 错误能回到模型和用户，成功成果不会丢。
- 权限和副作用可从真实执行记录核对。
- 网页端和终端端使用同一个 Agent 核心。
